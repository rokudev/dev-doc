<p>The Roku socket-based BrightScript debug protocol enables Roku app development to be tightly integrated into IDEs. A tight integration helps expedite development as an IDE could be used to do the following:</p><ul>    <li>Write code using BrightScript syntax-directed editing and highlighting.</li>    <li>Upload and run the app directly to the Roku media player.</li>    <li>Communicate app stops and failures.</li>    <li>Stop a running app.</li>    <li>Inspect variables and stack traces of a stopped app.</li>    <li>Step through a thread.</li>    <li>Insert dynamic breakpoints.</li>    <li>Resume a stopped app (if a fatal error has not occurred).</li></ul><blockquote>    <p>This protocol may be used in an interactive debugging session. Do not use it for storing data in a static file.</p></blockquote><h2 id="network-format">Network Format</h2><p>The network format of the protocol adheres to the following rules:</p><ul>    <li>Numeric values are sent in little-endian order.</li>    <li>Data types are sent as a network byte stream in little-endian order.</li>    <li>String values are encoded as UTF-8.</li></ul><h2 id="debugging-target-startup-sequence">Debugging target startup sequence</h2><p>The handshake consists of the following data being sent by each end of the connection:</p><pre><code>struct HandshakeToDVP &#123;  uint64 magic_number;&#125;;struct HandshakeFromDVP &#123;  uint64 magic_number;  uint32 protocol_major_version;  uint32 protocol_minor_version;  uint32 protocol_patch_version;  uint32 remaining_packet_length;  int64  platform_revision_timestamp;&#125;;</code></pre><table>    <thead>        <tr>            <th>Field</th>            <th>Type</th>            <th>Description</th>        </tr>    </thead>    <tbody>        <tr>            <td>magic_number</td>            <td>uint64</td>            <td>The Roku Brightscript debug protocol identifier: <code>0x0067756265647362LU</code>. This is equal to <code>29120988069524322LU</code> or the little-endian value: <code>b'bsdebug\0'</code>.</td>        </tr>        <tr>            <td>protocol_version</td>            <td>uint32</td>            <td>The Roku OS version specific protocol. The debugger client must be updated to the protocol version number or disconnect.</td>        </tr>    </tbody></table><h2 id="debugger-request-format">Debugger Request Format</h2><pre><code>struct DebuggerRequest &#123;  uint32 packet_length;  uint32 request_id;  uint32 command_code;  uint8 command_arguments;&#125;;</code></pre><table>    <thead>        <tr>            <th>Field</th>            <th>Type</th>            <th>Description</th>        </tr>    </thead>    <tbody>        <tr>            <td>packet_length</td>            <td>uint32</td>            <td>The size of the packet to be sent. Example: <code>(4 + 4 + 4 + sizeof(ARGUMENTS))</code>.</td>        </tr>        <tr>            <td>request_id</td>            <td>uint32</td>            <td>The ID of the debugger request (must be &gt;= 1).</td>        </tr>    </tbody></table><h2 id="debugger-response-format">Debugger Response Format</h2><pre><code>struct DebuggerResponse &#123;  uint32 packet_length;  uint32 request_id;  uint32 error_code;  uint32 error_flags;  uint8[] error_data;  uint8 data;&#125;;</code></pre>
